# FSLogix Profile Manager – Changelog

## v0.6.0 – Major Feature Release

This release implements all planned v0.6 features, significantly expanding the tool's capabilities.

### New Features

1. **SID Column with Per-User Breakdown**
   - New "SIDs" column in the grid showing aggregated SIDs per user
   - Abbreviated display for users with many SIDs (e.g., "S-1-5-21-xxx; ... (+3 more)")
   - Full SID list available via tooltip on hover
   - Tracks which profile roots each user appears in (for multi-root scenarios)

2. **CSV Export**
   - New "Export CSV" button in the toolbar
   - Exports current filtered grid view to CSV file
   - Includes all columns: User, Container Count, Profile GB, Office GB, Total GB, Last Write, SIDs, Root Folder
   - Proper CSV escaping for values containing commas or quotes

3. **Per-Column Sorting**
   - Click any column header to sort ascending/descending
   - Sort indicator (glyph) shows current sort direction
   - Sorts by appropriate data type (numeric for sizes, date for Last Write, count for SIDs)
   - Persists sort across filter operations

4. **Multi-Root / Cloud Cache Support**
   - Profile Root field now accepts semicolon-separated paths
   - Example: `\\server1\profiles;\\server2\profiles`
   - Merges results from all roots, aggregating by username
   - Tracks which roots each user's containers came from
   - Hint text below the input field explains the format

5. **Rename Preview Dialog**
   - New "Preview" checkbox (enabled by default) next to Reset Profile button
   - When enabled, shows a detailed preview before any rename operation
   - Lists all files with: User, Current Path, New Path, Status
   - Status indicators: OK (green), IN USE (red), EXISTS (yellow), MISSING (yellow)
   - Summary shows total files and count of in-use files
   - Proceed or Cancel from the preview dialog

6. **Open-Handle Detection**
   - New "Skip in-use" checkbox (enabled by default)
   - Detects if VHD/VHDX files are currently mounted or locked
   - In-use files are highlighted in the preview dialog
   - When enabled, skips in-use files during rename (logs them as skipped)
   - Uses file system lock detection via exclusive open attempt

7. **Light/Dark Theme Support**
   - New Theme dropdown in the toolbar (Light/Dark)
   - Light theme: Traditional light background with dark text
   - Dark theme: Dark gray background with light text, optimized for low-light environments
   - Theme applies to: form, grid, buttons, text boxes, checkboxes, log panel
   - Highlight colors adjust per theme (MistyRose for light, dark red for dark)

8. **Embedded Logging Panel**
   - Resizable log panel at the bottom of the window (drag splitter to resize)
   - Real-time operation logging with timestamps
   - Log levels: INFO, WARN, ERROR
   - "Clear" button to reset the log
   - Logs all operations: load, filter, sort, export, rename actions
   - Keeps last 500 messages in memory
   - Monospace font (Consolas) for readability

9. **Manual Rescan Button**
   - New "Rescan" button next to "Load Profiles"
   - Rescans all configured roots without restarting the tool
   - Useful after external changes to the profile storage
   - Logs the rescan action

### UI Changes

- Window size increased to 1100x800 to accommodate new features
- SplitContainer divides the main grid from the log panel
- Grid now has 8 columns (added SIDs column)
- Controls repositioned for the wider layout
- All controls properly anchored for window resizing

### Technical Improvements

- `Get-FSLogixProfiles` now accepts array of profile roots
- Profile objects now include `SIDs` (HashSet) and `ProfileRoots` (HashSet) properties
- `Rename-FSLogixProfileObject` now accepts `-CheckInUse` parameter
- New helper functions: `Test-FileInUse`, `Get-InUseContainers`, `Export-GridToCSV`, `Add-LogMessage`, `Apply-Theme`
- Theme definitions stored in `$script:Themes` hashtable for easy customization
- Log messages stored in `$script:LogMessages` ArrayList

## v0.5.2  (Profile-only & ODFC-only targeting, “Reset Profile” UI)

- Added a new **“Only Profile containers”** checkbox, alongside:
  - **“Only ODFC (Office) containers”**

- The tool now supports three clear retirement/reset modes:
  1. **ODFC-only**:
     - `Only ODFC (Office) containers` checked.
     - `Only Profile containers` unchecked.
     - Only containers whose filenames match `odfc` or `office` are renamed.
  2. **Profile-only**:
     - `Only Profile containers` checked.
     - `Only ODFC (Office) containers` unchecked.
     - Only non-ODFC containers (typical user profile VHD/VHDX) are renamed.
  3. **All containers**:
     - Both checkboxes unchecked.
     - All containers for the selected users are renamed.

- Ensured the two checkboxes are **mutually exclusive**:
  - Checking one automatically unchecks the other.
  - If both are true at the function level, no action is taken and a warning is logged.

- UI alignment and labeling:
  - Bottom-row controls (status label, ODFC/Profile checkboxes, Reset/Close buttons) are aligned in a single horizontal row for a cleaner look.
  - Main action button text changed from “Retire (rename) selected” to **“Reset Profile”**.
  - Confirmation dialog updated to match the new wording and still clearly indicate that containers will be renamed to `*-old.vhd(x)`.

- Under the hood:
  - `Rename-FSLogixProfileObject` now accepts `-OnlyOdfc` and `-OnlyProfile` switches.
  - Filters the profile’s `ContainerFiles` collection based on these flags.
  - Logs the final container list that will be processed (or skipped).

## v0.5.1  (Rename-based “retire” behavior)

- Changed cleanup semantics from **delete** to **rename**:
  - Instead of deleting FSLogix containers, the tool now **renames** them by appending `-old` before the extension.
  - Examples:
    - `Profile_username_SID.vhdx` → `Profile_username_SID-old.vhdx`
    - `ODFC_username_SID.vhd` → `ODFC_username_SID-old.vhd`
  - This provides a safer rollback path and avoids immediate data loss.

- Updated per-user operation:
  - New core function `Rename-FSLogixProfileObject` replaces the delete function.
  - Logs are now written as `FSLogix_Rename_username_YYYYMMDDHHMMSS.log`.

- Updated UI labels:
  - Bottom action button text changed to “Retire (rename) selected”.
  - Checkbox text for Office-only mode changed to “Only ODFC (Office) containers”.
  - Confirmation dialog explicitly states files will be renamed to `*-old.vhd(x)`.

- WhatIf behavior:
  - When **WhatIf (simulate)** is enabled, the tool logs what would be renamed without making changes.
  - Log entries use messages like:
    - `WHATIF: Would rename <oldPath> -> <newPath>`.

## v0.5  (FSLogix Horizon IC-focused build)

- Added **versioning**:
  - Script-level `$appVersion` variable set to `0.5`.
  - Version string displayed in the window title.
  - Version label displayed on the top row.

- Stabilized discovery logic for environments using folder naming:
  - `username_S-1-5-21-XXXXXXXXX-XXXXXXXXX-XXXXXXXXX-XXXXX`
- Enumerates all `*.vhd` / `*.vhdx` containers under the profile root and groups them by username.
- Shows per-user aggregates:
  - Container count
  - Profile size (GB)
  - Office/ODFC size (GB)
  - Total size (GB)
  - Last write time
  - Root folder

- Added **Delete only ODFC** mode (now evolved to Office-only rename/reset mode).
- Maintained **WhatIf (simulate)** mode:
  - On by default.
  - Log files record what would be done instead of actually performing actions when enabled.

- Implemented **row highlighting**:
  - **Highlight > X GB** controls:
    - Checkbox to enable/disable highlighting.
    - Numeric threshold in GB.
  - Rows where `TotalSizeGB >= threshold` are highlighted (MistyRose background).

- Manual DataGridView population:
  - Grid is populated row-by-row using stored profile objects in `Row.Tag`.
  - Avoids data-binding quirks and ensures reliable display even with complex objects.

- UI layout refinements:
  - Controls placed on two clean top rows:
    - Row 1: Profile Root, Load Profiles, version label.
    - Row 2: Filter, Last used > X days, WhatIf (simulate), Highlight > X GB.
  - NumericUpDown controls positioned to avoid clipping by the form edge.
  - Bottom row: Status, container targeting toggles, main action button, Close.
